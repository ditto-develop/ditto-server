# ADR 0039 — 운영 데이터를 지우는 어드민 QA 도구는 환경변수 스위치 뒤에 둔다

- 상태: Accepted (2026-10-05)
- 근거: discussion (#263, #265)

## Context

QA는 퀴즈를 풀고 매칭을 돌려 본 뒤 지우고 다시 하는 일을 반복한다. 그런데 매칭 기록(`match_candidate`·`personal_match`·`group_match`)이 생긴 퀴즈셋은 일반 삭제가 거부된다(#257). 그 주의 채팅·평가·재매칭이 이 셋을 기준으로 남기 때문이다. 매칭을 한 번 돌린 셋은 지울 수도, 같은 셋으로 다시 돌릴 수도 없었다.

지금은 운영 환경에서 QA를 한다. 배포는 `prod` 프로필 하나라 프로필로 local 전용 기능을 만들 수 없다(ADR 0038 과 같은 사정). 실회원이 들어오면 이런 도구는 꺼야 한다.

## Decision

매칭 기록 초기화·답·진행 초기화·강제 삭제는 `ditto.admin.qa-tools.enabled`(`ADMIN_QA_TOOLS_ENABLED`, 기본 꺼짐)가 켜져 있을 때만 동작한다. 꺼져 있으면 퀴즈셋 상세의 카드와 참여 현황의 회원별 버튼을 숨기고, 요청이 와도 아무것도 지우지 않고 거부한다. 지금은 `.aws/task-definition.json` 에서 켠다.

- 매칭 기록 초기화가 지우는 것: 매칭 기록(후보·1:1 신청·그룹과 초대·재매칭), 거기서 열린 채팅방과 평가, 이들을 가리키는 알림과 매칭 결과 알림. 퀴즈셋·답·진행은 남겨 같은 셋으로 매칭을 다시 돌릴 수 있다.
- 매칭 기록 초기화는 이번 운영 주 셋만 받는다. 다른 주 셋은 다시 돌려도 앱에 보이지 않고, 그대로 두면 다음 목요일 배치가 다시 매칭해 결과 알림을 보낸다. 그런 셋은 강제 삭제로 정리한다.
- 강제 삭제는 매칭 기록 초기화 뒤 일반 삭제(`QuizSetDeleter`)를 부른다. 일반 삭제의 거부 규칙은 그대로 둔다.
- 답·진행 초기화(#265)도 이번 운영 주 셋만 받는다.
  - 셋 전체: 매칭 기록을 먼저 지우고 답·진행을 지운다. 퀴즈셋·문항은 남긴다. 답만 지우면 남은 후보 점수의 근거가 사라진다.
  - 회원 한 명: 매칭 기록이 없는 셋에서만 된다. 후보·그룹에서 한 명만 빼낼 수 없다. 결과 0건으로 매칭이 돈 셋도 여기 들어오므로 그 회원의 매칭 결과 알림도 지운다.
- 매칭 기록을 지우는 코드는 더미 정리와 같이 쓴다(`MatchingRecordEraser`). 무엇을 지울지만 호출자가 정한다.
- 신고·제재는 퀴즈셋이 아니라 회원 기록이라 지우지 않는다.

## Consequences

- 얻음: 매칭이 끝난 셋으로 QA를 반복할 수 있다. 실서비스 전환 때 환경변수 하나로 끈다. 일반 삭제 규칙은 바뀌지 않는다.
- 비용: 켜져 있는 동안 어드민이면 누구나 실회원끼리 열린 방·메시지·평가와 실회원 답까지 되돌릴 수 없게 지울 수 있다. 퀴즈 기간이 지난 뒤 답을 지우면 시간 오버라이드 없이는 앱에서 다시 풀 수 없고, 오버라이드는 모든 회원에게 적용된다. 기본값이 꺼짐이라 환경변수를 빠뜨리면 기능이 안 보인다.
- 후속/연쇄: 더미 생성·QA 콘솔·시간 오버라이드는 아직 이 스위치를 따르지 않는다(#264).
