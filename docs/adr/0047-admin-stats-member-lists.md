# ADR 0047 — 운영 지표에서 운영자가 챙겨 볼 회원 목록은 id·닉네임·건수만 내린다

- 상태: Accepted (2026-10-23)
- 근거: code-evidence (#348)

## Context

기획 운영 지표 정의서 P1 에 "연속 미매칭 유저"와 "신고 상위 유저"가 있다. 둘은 숫자가 아니라 운영자가 누구에게 연락하거나 검토할지 고르는 목록이라 누구인지 보여야 쓸 수 있다.

[ADR 0046](0046-admin-stats-render-in-browser.md)은 회원 행을 브라우저에 보내지 않는다고 정했다. 개인정보가 나가고 양이 커지기 때문이다.

## Decision

- 운영자가 챙겨 볼 목록은 예외로 회원 행을 `StatsPageData` JSON 에 넣는다. 넣는 값은 회원 id 와 닉네임, 목록에 필요한 건수뿐이다.
- 닉네임을 누르면 회원 관리 검색(`/admin/members?q=%23{id}`)으로 그 회원만 찾는다. 어드민에 회원 상세 화면이 없어서 검색 결과로 보낸다.
- 신고 상위는 서버가 많은 순으로 10명까지만 내린다. 연속 미매칭은 조건에 맞는 회원 전부를 내리고 화면이 카드 안에서 스크롤한다.

## Consequences

- 닉네임은 회원 관리·신고 검토 화면에 이미 나오는 값이라 어드민이 보는 범위는 넓어지지 않는다. 이메일·생년월일 같은 값은 여전히 내리지 않는다.
- 연속 미매칭은 인원 제한이 없어 성사가 드문 회차에는 목록이 길어진다. 페이지 크기가 문제가 되면 그때 상한을 둔다.
- 목록을 하나 더할 때도 이 범위(id·닉네임·건수)를 넘기려면 새 ADR 이 필요하다.
