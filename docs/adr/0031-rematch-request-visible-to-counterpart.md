# ADR 0031 — 재매칭 의사를 상대에게 공개한다 (상호 선택 비공개 → 신청/수락)

- 상태: Accepted
- 근거: Issue #215, 기획 "알림 문구" 표의 "재매칭 신청 받음" (2026-09-24 확정)

## Context

재매칭은 그룹 채팅이 끝난 뒤 멤버끼리 "1:1로 다시 만나고 싶어요"를 고르는 기능이다. 지금까지는 **상호 선택 비공개**였다 — 둘 다 원했을 때만 성사를 알리고, 한쪽만 원했거나 한쪽이 원하지 않으면 아무에게도 알리지 않았다. 한쪽만 원했다는 사실이 드러나면 "거절당했다"가 되고, 그룹에서 같이 놀던 사람 사이에서 그건 상처이며 선택받은 쪽은 압박을 느낀다는 판단이었다. 코드도 그 전제로 짰다: 두 선택 컬럼은 `private`, 외부 조회는 본인 값만 주는 `wantsOf()`, `submitWants()`의 검사 순서(인가 → 본인 상태 → 쌍 상태)까지 실패 응답의 오류 코드로 상대 제출 시각이 새지 않게 맞췄다([ADR 0012](0012-rematch-as-separate-table.md), [ADR 0011](0011-rematch-pessimistic-lock.md)).

기획 "알림 문구" 표에는 **"재매칭 신청 받음 — {닉네임}님이 다시 만나고 싶어 해요 / 수락하면 대화방이 열려요"**가 있다. 이 알림은 상대의 단방향 선택을 그대로 알리는 것이라 비공개 전제와 양립하지 않는다. 알림 하나를 넣는 문제가 아니라 모델을 고르는 문제였다.

## Decision

**신청/수락 모델로 바꾼다. 상대의 재매칭 의사를 공개한다.**

- **데이터 구조는 그대로 둔다.** `member1Wants`/`member2Wants`, 상태 `WAITING`/`MATCHED`/`CANCELLED`, 성사·취소 전이, 제출 최종(회수 불가), 행 잠금(ADR 0011) 모두 유지. "신청 받음"은 `상대 == true && 나 == null`로 **파생**한다. 별도 상태나 마이그레이션을 두지 않는다 — 두 사람의 독립 선택이라는 사실은 변하지 않았고, 바뀐 것은 그 선택을 보여 주는지 여부다.
- **노출 경로는 둘이다.**
  - 평가 대상 응답(`GET /api/v1/member-reviews`의 `targets[].counterpartWantsRematch`): `true` 받은 신청, `false` 상대가 원하지 않음, `null` 미제출 또는 1:1 평가. 거절 사실도 보인다.
  - 알림 두 종: `REMATCH_REQUESTED`(먼저 "원한다"를 낸 사람의 상대에게), `REMATCH_REJECTED`(쌍이 `CANCELLED(NOT_MUTUAL)`로 닫힐 때 원했던 쪽에게, 순서 무관). 성사는 기존 `REMATCH_MATCHED`(방 예약 시). `target_id`는 `rematch.id`, 쌍마다 한 번. 거절 알림은 표에 없어 문구는 확정 전이다 — "거절했어요"보다 부드럽게 "이루어지지 않았어요"로 둔다.
- **알림은 제출 커밋 뒤 컨트롤러가 판정한다.** 제출 서비스의 반환 타입(응답 DTO)을 바꾸지 않고, `RematchNotifier`가 쌍을 잠금 없이 다시 읽는다. 제출은 한 사람당 한 번이라 제출 직후의 쌍 상태가 곧 이번 제출의 결과다(ADR 0018의 요청 경로 규칙).
- `submitWants()`의 검사 순서는 그대로 두되, 그 순서의 근거였던 "비공개 계약" 설명은 코드와 문서에서 지운다. 순서 자체는 여전히 자연스럽다(인가 → 본인 → 쌍).

## Consequences

- **거절이 보인다.** 상대가 원하지 않는다고 내면 신청자는 알림과 화면으로 그 사실을 안다. 비공개 모델이 막으려던 상처가 생긴다. 기획이 "신청 받음" 알림을 표에 넣은 것을 그 대가를 감수한 결정으로 받아들였다.
- **먼저 원하지 않는다고 낸 쪽의 의사는 여전히 드러나지 않는다.** 신청이 없으니 알림도 없고, 상대가 뒤에 "원한다"를 내면 그 상대에게만 거절 알림이 간다. 비대칭이지만 신청/수락 모델에서 자연스럽다.
- **FE 변경이 따른다.** 평가 화면의 "신청 여부는 상대방에게 공개되지 않아요" 안내가 거짓이 되고, "받은 신청" 표시가 필요하다. FE 평가·재매칭 화면은 아직 서버 계약에 연결되지 않은 상태(`/api/v1/group-ratings`·`/api/v1/rematches/*` 호출)라, 연동할 때 함께 한다. 서버가 먼저 나가도 응답 필드 추가는 하위 호환이고 알림을 탭하면 평가 화면(재매칭 토글이 이미 있음)으로 간다.
- **그룹 멤버 N명에게 동시에 "원한다"를 내면 알림 N건이 나간다.** 쌍마다 독립이라 의도대로다.
- ADR 0012의 "비공개" 근거 문단과 ADR 0011의 검사 순서 설명은 이 결정으로 일부 소멸했다. 두 ADR은 테이블 분리·잠금이라는 본 결정이 유효하므로 Superseded 로 바꾸지 않고 이 ADR을 링크한다.
